# 《飞行小八戒》核心飞行原型 Brief

## 唯一验证问题

**“连续点击上升、停止点击下落”的冲量控制，在没有正式美术加成时，是否容易理解、可控并让人愿意立刻再玩一局？**

这轮原型不验证天宫美术、九种障碍、商业化或长期留存。一次原型只回答这一个问题。

## 原型约束

```text
CORE VERB:   连续点击获得向上冲量，停止点击后自由下落
THROWAWAY:   是；放在独立 prototypes/flight-feel/，验证后不直接升为正式代码
TIMEBOX:     90 分钟完成首个可玩版本，其后只做有记录的单变量调参
ART:         圆形/胶囊形玩家 + 矩形通道 + 内置字体
AUDIO:       无，或只用一个临时得分提示音
DEBUG HUD:   velocityY、isHolding、当前重力/推力、通道高度、FPS
```

## 必须具备

- 一个玩家占位体。
- 点击冲量/停止点击下落的飞行模型。
- 固定速度向左移动的矩形障碍。
- 固定的 5～10 个测试通道，不使用随机生成。
- 碰撞、得分、立即重开。
- 可现场调节重力、上升加速度、速度上限和通道高度。

## 明确不做

- 正式角色动画、天宫背景、动态障碍、完整 UI。
- 对象池、存档、音频系统、平台 SDK、复杂架构。
- 用美术润色掩盖操作本身的问题。

## 保留标准（KEEP）

由至少 3 名未参与开发的人无口头指导试玩：

- 在 `30 秒` 内主动理解连续点击和停止点击的作用；
- 在 3 次尝试内至少有 2 人能连续通过 5 个固定通道；
- 至少有 2 人在失败后主动选择“再来一次”；
- 玩家描述的失败原因主要是自己的操作，而不是“按了没反应”或“角色不受控制”。

达到标准后，在正式目录按技术设计文档重写可维护版本，不复制原型中的临时代码。

## 调整标准（REFACTOR）

玩家理解操作，但普遍在同一问题上失败时，只调整一个变量后复测：

- 上升过猛：降低上升加速度或最大上升速度。
- 下坠过快：降低重力绝对值或最大下降速度。
- 反向切换太迟钝：减小速度上限或调整净加速度。
- 通道看得懂但过不去：先扩大通道，不立即改飞行模型。

## 推翻/改操作标准（KILL OR PIVOT）

经过最多 3 轮单变量调参后，若多数外部玩家仍无法在 30 秒内理解或稳定控制，则暂停正式资产制作，并对比测试“点击产生一次向上冲量”的传统方案。不能因为已经画了耳朵动画而继续保留不好玩的操作。
